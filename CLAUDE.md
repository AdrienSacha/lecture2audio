# lecture2audio

Turns a lecture (a recording, a transcript, slides, or slides alone) into a clear spoken explanation, recitation notes typeset with LaTeX, and course notes for studying. It is not a summarizer: everything the teacher taught must stay in the script. Only noise is removed. Gaps the lecture leaves (untaught slide ideas, undefined terms, assumed fundamentals, skipped steps) are filled from web sources whose quotes code has checked, and marked as such.

# Commands

- All tests (no key, no model, needs ffmpeg): `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m unittest discover -s tests`
- One test file: `PYTHONPATH=src python3 -m unittest tests.test_outline`
- Whole pipeline without models: `PYTHONPATH=src python3 -m lecture2audio build examples/sample_transcript.txt --llm dry --tts fake --language en --max-part-words 60 --out /tmp/l2a`, then read `/tmp/l2a/sample-transcript/report.md` and `index.md`
- One folder, no flags: `PYTHONPATH=src python3 -m lecture2audio ./lecture_folder/ --llm dry --tts fake` (no command means `build`; the folder's recording or transcript, slides and glossary are found by `sources.discover_inputs`)
- The app: `.venv/bin/python -m lecture2audio app` (or double-click `app/Lecture2Audio.app`); it serves one page on 127.0.0.1:8765 and runs the command line in a subprocess.
- Slides alone: `PYTHONPATH=src python3 -m lecture2audio text deck.pdf --llm dry` (a `.pdf` or `.pptx` as INPUT, or a folder that holds only slides). `--project` adds `project.pdf`; `--no-pdf` or `L2A_PDF=0` writes only the `.tex` files (the tests set it).
- Real lectures to try a change on: `python tests/real_data.py` downloads slides, captions and transcripts of MIT OpenCourseWare into `tests/.cache/` (not committed).
- The vault and the ledger of a run: `/tmp/l2a/sample-transcript/vault/` (open it as an Obsidian vault) and `/tmp/l2a/sample-transcript/ideas.csv`
- Chapters of the result: `ffprobe -v error -show_chapters <file>.m4a`
- After any change: run the tests and the dry build above. The work is done when both pass.

# Conventions

- Use the latest official SDKs and state-of-the-art libraries rather than hand-written code (user's decision, November 2026): the `openai` SDK for every OpenAI-compatible API (OpenAI, DeepSeek, Kimi, OpenRouter, local servers) and the `anthropic` SDK for Claude, with their streaming, retries and typed errors. Add a dependency when it is the best tool for the job; pin a minimum version in `pyproject.toml` and install with `uv` into `.venv`. Prefer the most efficient correct code.
- Heavy model packages (mlx-audio, mlx_whisper, faster_whisper, pypdf, rapidocr, pypdfium2) are imported inside the function that needs them, so the text pipeline starts fast and runs on machines without them.
- Prompts live in `src/lecture2audio/prompts/*.md`. The JSON each prompt asks for is checked by a gate in `pipeline.py`, `outline.py` or `enrich.py` (`validate_part`, `validate_verify`, `validate_spoken`, `parse_outline`, `validate_coverage`, `validate_idea_list`, `validate_termbase`, `validate_research`, `validate_uses`, `recitation.validate_section`, `project.validate_project`). When a prompt's output format changes, change its gate, `dry_run_handler` in `llm.py`, and the tests in the same change.
- `dry_run_handler` and the test harness recognise each prompt by a phrase in it: "You build the outline", "strict reviewer", "exact words a voice should say", "You find the gaps", "You list the atomic ideas", "You build the termbase", "You research one gap", "You check terminology", "You write the recitation notes", "You design the project". The slide reader (`prompts/slide.md`) returns plain text, not JSON, and is not called by the dry model. `test_pipeline.Harness` sends any unknown prompt to the rewrite handler. Keep these phrases when editing prompts.
- Languages: English and French. Any fixed wording spoken by the program (part titles, previews, quiz) is in `WORDING` in `pipeline.py`; add both languages together.
- Every stage caches its result under `out/<name>/` (`outline.json`, `coverage.json`, `ideas/`, `termbase.json`, `research/`, `rewrite/`, `audit.json`, `factcheck/`, `spoken/`, `audio/` with `roundtrip.json`, `parts/`, `course/` with `revised_*.json` and `cold_revised_*.json`, `slides/`, `recitation/`, `project.json`). `recitation.tex`, `project.tex` and their PDFs are rebuilt from the stage results; a PDF is built again only when its `.tex` changed. A new stage needs its own cache and an entry in `STAGES` in `stages.py`, after the stages it needs: `--redo`, `stages.check` and the stage section of `report.md` are computed from it. `ideas.csv` and `anki.csv` are not caches: they are rebuilt from the stage results on every run (`ledger.py`).
- The idea ledger (`ideas.csv`, columns `idea_id,node_id,kind,statement,source_units,covered_in_card,status`) is the thread through the stages: `ledger.Ledger` is seeded after `run_ideas` (one call per part, ids scoped to the part: `T3.12`) and rewritten as each part finishes its script (`run_parts(on_done=...)`) and its cards (`CoursePipeline.run(on_done=...)`); each update rebuilds every row from the seed and the results so far (`apply_script`, `apply_cards`) and replaces the file atomically, so it is current and never says more than the saved results. A stage that sees ideas must answer for every one of them (`validate_ideas`, `validate_judgement`); `report.md` lists every idea that did not arrive.
- A figure frame has exactly one of `mermaid` and `ascii` (`course_schema.Frame`); the template wraps each frame in a `[!figure]` callout with a ```mermaid or ```text block.
- The script is claim-anchored: with ideas, every "lecture" sentence carries `ideas` (ids of the part). `pipeline.idea_citations` blocks an idea no sentence cites (`idea_uncited`) and warns on a lecture sentence citing none (`unledgered`). The idea listing (`enrich.IdeaList`, Pydantic) has no minimum count: every unit is in an idea or in `no_content`, and `run_ideas` re-asks for unaccounted units with "fewer is fine" wording, never a bare validation error (padding: arXiv 2610.30997).
- A card has `plain` ("In short", required, blocking `no_plain`; sentence length is only a warning), optional `proof`; a part has `exercises` (question, steps, answer, covers) that the course judge solves again (`EXERCISE_STATUSES`). After the cold read, parts with loose ends get one revision (`CoursePipeline.revise`), kept only if not worse.
- Output files written for the user (`script.md`, `index.md`, `questions.md`, `glossary.md`, `report.md`, the vault notes) use full sentences in a formal register.
- The model never writes a LaTeX document. It writes blocks of content (`recitation.Block`, `project.Project`) and `latex.py` typesets them: every text field goes through `latex.inline` or `latex.block` (escaped, math kept), math and TikZ are refused by `latex.tex_error` when they hold a command that reads files, writes files or defines macros, and both ends of every link are created by code. Layout lives in `assets/preamble.tex` only.
- Two interfaces: the app (`app.py`, `assets/app.html`, one self-contained page, standard library server) and Obsidian. The app follows a run through the stage events of `stages.Tracker` (`@@stage {...}` lines when `L2A_EVENTS` is set), never through the wording of the log. A new stage needs a `track("name")` call in `cli.run`. Vault templates are in `src/lecture2audio/assets/*.j2`; labels in both languages are in `LABELS` in `course_render.py`.

# Design decisions (keep unless the user decides otherwise)

Full sources and the ideas not built yet: `docs/research-notes.md`. Update it when a decision changes.

- A fixed chain of model calls with code checks between them, not agents that talk to each other. 2026 studies found that a single strong model matches or beats multi-agent setups at equal token budget (arXiv 2601.12307, 2604.02460, 2606.05670), and this task is sequential.
- The chain is a declared graph owned by code (`stages.py`); a model never picks the next stage, because model routing and whole-procedure context each cost tens of points of repeated-run success (STAGE, arXiv 2608.22538; ADR-0003).
- One outline call plans the whole lecture. Parts are then independent, so they run in parallel (`--workers`).
- The outline never moves material across parts, and every move inside a part is logged in `report.md`. Every unit is used exactly once (in a node or in noise); noise is listed in full at the end of `report.md`.
- At most three levels: part, point, sub-point. A node with a single child is folded into its parent by code.
- Code gates run before any model judge, because they cost nothing and catch most format faults (arXiv 2609.31937).
- The verifier must give a status for every node of the checklist; the verdict is computed by code from those statuses and the issues, never taken from the model.
- The retry loop keeps the best attempt and replaces it only by a strictly better one, and feedback is built from the best attempt, because a repair can damage a correct script (arXiv 2607.17641). Default: two repairs at most. A repair is bounded: when every blocking issue can be placed in a section (or the recap or the questions), only those are rewritten and code keeps the rest word for word (`repair_plan`, `splice_repair`; arXiv 2611.05166); otherwise the whole part is rewritten. The course cards are repaired the same way, by section and for the exercises, and so is the cold-read revision (`card_scope`, `splice_cards` in `course.py`). Each repair is listed in `report.md`.
- Independent second opinions are reported, never acted on: MiniCheck (`factcheck.py`, `--factcheck`) checks each lecture sentence against the units of the ideas it cites; the voice round trip (`assemble.repair_chunks`, on by default when recognition is installed) re-voices chunks heard wrong and keeps the best take. Speech recognition drops known hallucination phrases and third repeats (`transcribe.clean_segments`) and reports them.
- One planted-omission test per run checks that the verifier is not passing everything (arXiv 2610.11464). Do not remove it to save a call. The same holds for every other judge of completeness: the gap search (a blanked unit, `audit_coverage`), the idea listing (a planted fact, `audit_ideas`) and the course judge (an emptied card, `CoursePipeline.audit_judge`, scored on the judge's own verdict, not on the code checks after it). `--no-audit` skips them all.
- A judge's "taught" is checked by code: the numbers of the idea that the transcript holds must be in the script (`_verify`) or in the cards named, figures, tables and code included (`_judge`, `numbers_lost`; exponents and indices are skipped because they are said in words). When they are not, code does not overrule the judge: the idea is `disputed` in the ledger, listed in `report.md`, and the issue `idea_numbers` is soft. An audit scores the judge's own verdict (`judged`), never the code checks after it. A failed audit (model error) is not cached, so it runs again next time.
- Previews ("This part has three points. First, ...") are assembled by code from the model's phrases, so they always match the sections.
- Gaps (slide idea not taught, term never defined, fundamental assumed, step skipped) are filled only with facts found online whose quote code finds word for word in a page (`check_facts`). Such sentences are tagged `external` with a source id, marked aloud by a natural phrase once per passage, and listed in `script.md` and `reference.md`. Research is `native` (the provider's own web search, Anthropic and OpenAI) or `loop` (the program runs `web_search` and `fetch_page` for any model that calls tools: DeepSeek, Kimi, OpenRouter, any compatible API, local; engines in `web.make_search`). Every gap is researched; `--research-depth` sets the tool calls per gap, there is no cap on gaps.
- One definition per term (`termbase.json`). Every term a definition relies on has its own entry, and code moves it before the terms that need it (`build_termbase`). Code flags a confusable word the sources never use (`stray_terms`) and a term used before its part; a separate judge checks every occurrence against the definition, because one judge for many criteria mixes them up.

# Gotchas

- Slides: `sources.load_slides` reads a PDF's text layer with pypdf; a page with fewer than `ocr.MIN_CHARS` characters, and every picture of a PowerPoint slide, goes through OCR (`ocr.py`, RapidOCR, extra `.[ocr]`), cached by content in `slides_ocr.json`. `sources.merge_overlays` blanks a PDF page whose lines are all on the next page (animation steps), so page numbers stay and `select_slides` skips it. Pages that stay empty, or that need OCR when it is not installed, are listed in the "Slides" section of `report.md` and never stop the run.
- The text of a slide PDF loses its formulas (a sum sign comes out as "L") and some fonts garble the words; no PDF reader repairs this (`sources._pdf_pages`, `garbled_share`). With `--llm anthropic` or `openai` the pages are read by sight (`slides.py`, `--read-slides`); with the default DeepSeek models they are not, so a deck of formulas needs a transcript beside it or a model that reads images.
- The PDFs need LuaLaTeX with latexmk (MacTeX, TeX Live) or tectonic; `latex.build_pdf` goes on past errors and returns them, and `report.md` lists them. TikZ figures are compiled alone with `pdflatex` before they are accepted.
- The architecture decisions of November 2026 (LaTeX documents, slides as a source, the project, the local app, hosting) are in `docs/adr/0004-documents-slides-and-the-app.md`, with the open risks.
- `.venv` was created on the user's Mac; it does not run in a Linux sandbox. There, the system `python3` lacks the dependencies (`latex2mathml` among them): create a throwaway environment outside the repository with `uv venv /tmp/l2a-venv && VIRTUAL_ENV=/tmp/l2a-venv uv pip install -e .` and run the tests and the dry build with `/tmp/l2a-venv/bin/python`.
- Run everything with `.venv/bin/python` (or `uv run lecture2audio ...`): the speech and voice packages live only there. The default voice is Ming-3.0-tts-0.5B (MIT) through mlx-audio (`--tts ming`, built-in voice `US_James`); its weights (about 3 GB) live in the Hugging Face cache, `~/.cache/huggingface/hub`. Fish Audio Drama 3 (best open voice) was tried and removed: its 4-bit build needs about 24 GB and swapped this 32 GB Mac.
- Defaults (user's choice, quality first): `--llm deepseek` with `deepseek-flash` (V4.1 Flash, thinking on: keep it on, structured output costs open models accuracy unless they reason first, arXiv 2604.03616) writing and `deepseek-v4-pro` checking, DeepSeek search for research, `--language en`, Whisper large-v3, `--tts auto` (Ming in English, Qwen3-TTS `mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-bf16` in French, which Ming does not speak), `--max-part-words 1500`. For `--llm anthropic`, `claude-sonnet-5-5` and `claude-opus-5-5`; for `--llm openai`, `gpt-6.1-sol` and `gpt-6-astra`; kimi, openrouter, compat and local have no default. Real API calls have not been tested yet for any provider.
- Each hosted provider reads only its own key variable (`PRESETS` in `llm.py`), and the local client never sends `OPENAI_API_KEY` (it uses `L2A_LOCAL_API_KEY`), so no key leaks to another host.
- `--vault-dir` defaults to `L2A_VAULT_DIR`, and then `--open-obsidian` is on: the run ends with `open "obsidian://open?path=..."` (macOS only; elsewhere the link is printed). Tests remove `L2A_VAULT_DIR` from the environment so that they never write into a real vault.
- `--course` is on by default (`--no-course` skips the vault); the audio of each part is encoded a second time into `parts/` and copied into the vault's `audio/`, which doubles the disk use of the audio.
- The atomic ideas are listed one call per part (`run_ideas`, `prompts/ideas.md`), so no output limit cuts the list on a long lecture; the gap search stays one call over the whole lecture because a gap (a term used in part 2, defined in part 5) needs it. A part whose list keeps failing its gate is left empty, named in `report.md` and not cached. The architecture and its open risks are in `docs/adr/0001-pipeline-architecture.md`, `docs/adr/0002-grounding-plain-layer-voice-checks.md` and `docs/adr/0003-declared-stage-graph.md`.
