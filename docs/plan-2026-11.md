# Plan, November 2026

Three work streams, run in parallel by separate agents. Each stream owns its files, so no two agents edit the same file.

## A. Research update (owner of `docs/research-notes.md`)

- New sources must be published in 2026. The existing older references stay.
- Search for new evidence from top-tier venues only: journals ranked Q1 (Scimago) and conferences ranked A* (CORE), such as ACL, EMNLP, NAACL, NeurIPS, ICLR, ICML, CHI, Interspeech, ICASSP; journals such as *Educational Psychology Review*, *Review of Educational Research*, *Psychological Bulletin*, *Computers & Education*, *Learning and Instruction*, *TACL*, *JMLR*. Add high-quality engineering blogs (Anthropic, OpenAI, Google Research, Hugging Face) as practitioner sources, labelled as such.
- Topics: spoken and audio-only learning (podcasts, narration, speech rate, segmenting), signaling in audio, retrieval practice in audio, LLM faithfulness and omission detection in rewriting and summarisation, LLM-as-judge reliability, verify-repair loops, TTS intelligibility and listening comprehension.
- Verify every citation (venue, year, volume, pages, DOI). Correct the existing references flagged as "from memory" in section 6.
- For each new source, state what it changes in the build, or say that it changes nothing. Add new ideas to section 4.

## B. Model clients (owner of `llm.py`, the model parts of `cli.py`, the OpenAI part of `tts.py`, `tests/test_llm.py`)

- Check each request against current official documentation: Anthropic Messages API, OpenAI Chat Completions (and Responses, if needed), OpenAI speech API, and local OpenAI-compatible servers (Ollama, LM Studio, llama.cpp, vLLM).
- Known suspects: OpenAI reasoning models reject `max_tokens` and need `max_completion_tokens`; `message.content` can be null (refusal); no default models for `--llm openai`; local servers may ignore token limits or return reasoning text; Anthropic stop reasons other than `max_tokens` (`refusal`, `pause_turn`); retry on `overloaded_error`; `retry-after` header.
- Standard library only. Tests use a fake HTTP layer, no network.

## C. Graphical interface (owner of `gui.py` and `tests/test_gui.py`)

- A local web page served by the standard library (`http.server`), opened in the browser. No new dependency.
- Form for every useful option of `build` and `text`: input file, slides, glossary, language, providers and models for rewrite and verifier, base URLs, API keys for the session, voice options.
- Runs the existing command line in a subprocess and streams its log to the page. Shows the outputs when done: `script.md`, `report.md`, `questions.md`, and an audio player with the chapters.
- Binds to 127.0.0.1 only. Never writes API keys to disk.

## Integration (main session)

- Add `lecture2audio gui` to `cli.py`, update `README.md` and `CLAUDE.md`.
